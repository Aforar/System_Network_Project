## 2. Executive Project Summary

This project involved designing, deploying, configuring, and validating a two-site Microsoft Active Directory infrastructure using Windows Server 2022 and VMware Workstation.

The primary objective was to build a functional enterprise-style directory services environment that connects a Headquarters (HQ) network with a Branch network.

The infrastructure was designed around a single Active Directory forest and domain, `adlab.test`, with two domain controllers distributed across separate network subnets and Active Directory sites.

The implementation included:

- Virtual infrastructure preparation and operating system installation.
- Network segmentation and inter-site routing.
- Active Directory Domain Services deployment.
- DNS configuration and domain controller promotion.
- Active Directory Sites and Services configuration.
- Domain controller replication.
- Organizational Unit and security group design.
- Domain user and workstation management.
- Group Policy configuration.
- SYSVOL and NETLOGON validation.
- Authentication, DNS, replication, and policy testing.
- Controlled domain controller outage and recovery testing.

The project was completed through eight implementation and documentation phases, resulting in a functional multi-site Active Directory lab supported by technical documentation and validation evidence.

## 4. Final Infrastructure Overview

### 4.1 Physical and Logical Architecture

The lab uses four virtual machines:

| Virtual Machine | Operating System | Primary Role | IPv4 Address |
|---|---|---|---|
| DC-HQ | Windows Server 2022 | HQ Domain Controller, DNS, Global Catalog | `192.168.10.10` |
| DC-BRANCH | Windows Server 2022 | Branch Domain Controller, DNS, Global Catalog | `192.168.20.10` |
| CLIENT-HQ | Windows 11 Pro | Domain-joined workstation | `192.168.10.20` |
| RTR-HQ-BRANCH | Windows Server 2022 | Inter-site router | Two network interfaces |

### 4.2 Network Architecture

| Network | Subnet | Gateway |
|---|---|---|
| HQ | `192.168.10.0/24` | `192.168.10.254` |
| Branch | `192.168.20.0/24` | `192.168.20.254` |

VMware network mapping:

- `VMnet2`: HQ network.
- `VMnet3`: Branch network.

The routing virtual machine provides communication between the two subnets.

Two Group Policy Objects were implemented:

| GPO | Scope | Main Purpose |
|---|---|---|

The policies were validated using Group Policy refresh, `gpresult`, and client-side checks.

### Failure Recovery Test Summary

A controlled shutdown of `DC-BRANCH` was performed to test the availability of the HQ domain controller.

During the test:

1. `DC-BRANCH` was shut down.
2. `DC-HQ` remained operational.
3. `CLIENT-HQ` successfully authenticated using a previously logged-on account.
4. The logon server information identified `DC-HQ`.
5. `DC-BRANCH` was restarted.
6. Required services, replication, and SYSVOL/NETLOGON availability were checked again.

The test demonstrated basic service continuity through the HQ domain controller and successful recovery of the Branch domain controller.

It did not establish full production high availability or disaster recovery.

## 7. Technical Challenges and Lessons Learned

The implementation provided practical experience with several important infrastructure administration concepts.

### 7.1 Network Addressing and Routing

**Challenge:** Maintaining correct network addressing and avoiding IP conflicts between virtual network components.

**Lesson learned:**

- Plan IP addressing before deploying domain services.
- Assign static IP addresses to infrastructure servers.
- Keep gateway and DNS settings consistent with the network design.
- Validate connectivity between subnets before promoting additional domain controllers.

**Practical takeaway:** Network connectivity is a prerequisite for reliable multi-site Active Directory deployment.

### 7.2 DNS and Active Directory Integration

**Challenge:** Ensuring that domain controllers and clients can locate Active Directory services.

**Lesson learned:**

- Active Directory depends heavily on DNS.
- Domain controllers register service records used by domain clients.
- Incorrect DNS configuration can affect domain joining, authentication, and replication.
- DNS should be validated before investigating higher-level Active Directory problems.

**Practical takeaway:** DNS is a core dependency of Active Directory, not merely an optional network service.

### 7.3 Domain Controller Promotion

**Challenge:** Deploying an additional domain controller in a separate network.

**Lesson learned:**

- The existing domain must be reachable before promoting an additional domain controller.
- DNS configuration must support domain discovery.
- Inter-site connectivity is necessary for directory synchronization.
- Domain controller promotion must be followed by service and replication validation.

**Practical takeaway:** Adding a domain controller requires coordinated network, DNS, and directory services configuration.

### 7.4 Active Directory Sites and Services

**Challenge:** Representing the physical network topology correctly in Active Directory.

**Lesson learned:**

- Active Directory sites represent network locations rather than organizational departments.
- IP subnets must be associated with the correct site.
- Domain controllers must be assigned to their intended sites.
- Site links control the logical replication relationship between sites.

**Practical takeaway:** Correct site and subnet mapping helps Active Directory understand the network topology and select appropriate domain controllers.

### 7.5 Active Directory Replication

**Challenge:** Verifying that directory changes are synchronized between domain controllers.

**Lesson learned:**

- Replication must be monitored rather than assumed.
- DNS and network connectivity are important replication dependencies.
- `repadmin` provides useful visibility into replication status.
- A successful synchronization command should be followed by replication status verification.

**Practical takeaway:** Replication health is an essential part of maintaining a multi-domain-controller environment.

### 7.6 Group Policy Management

**Challenge:** Applying different policy settings at domain and organizational unit levels.

**Lesson learned:**

- GPOs should be linked at the appropriate scope.
- Domain-wide account policies and workstation-specific policies have different purposes.
- `gpupdate` refreshes policy processing.
- `gpresult` helps identify which policies are applied to a client.

**Practical takeaway:** Proper OU design and GPO scope management are important for consistent centralized administration.

### 7.7 Troubleshooting Methodology

**Challenge:** Identifying whether a problem originates from networking, DNS, Active Directory, replication, or Group Policy.

**Lesson learned:**

A structured troubleshooting sequence is more effective than changing multiple configurations without identifying the source of the issue.

The following diagnostic order was useful:

1. Check network connectivity.
2. Verify IP configuration and gateway settings.
3. Validate DNS resolution.
4. Inspect Active Directory services.
5. Check domain controller replication.
6. Verify SYSVOL and NETLOGON.
7. Inspect Group Policy results.

**Practical takeaway:** Troubleshooting should follow service dependencies, starting with the network and DNS before moving to higher-level directory services.
