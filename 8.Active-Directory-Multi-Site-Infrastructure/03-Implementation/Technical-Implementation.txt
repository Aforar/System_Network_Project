# 1. Environment Preparation

## 1.1 Objective

Prepare the virtualization environment, installation media, and project directory structure required to deploy the Active Directory multi-site infrastructure.

## 1.2 Virtualization Platform

The project uses VMware Workstation to create and operate the virtual infrastructure.

VMware virtual networking is used to simulate two separate enterprise network locations:

- Headquarters (HQ).
- Branch office.

## 1.3 Installation Media

The following operating system installation media is prepared:

- Windows Server 2022 ISO.
- Windows 11 Pro ISO.

The installation files are organized for use during virtual machine deployment.

SHA-256 checksums are used to verify the integrity of the installation media.

PowerShell command:

```powershell
Get-FileHash "C:\Path\To\WindowsServer2022.iso" -Algorithm SHA256
```

Repeat the command for the Windows 11 ISO.

The calculated hashes can be compared with trusted published checksums when available.

## 1.5 Project Organization

The project uses an organized directory structure to separate installation media, screenshots, and documentation.

The screenshots are organized by implementation phase to maintain traceability between configuration activities and validation evidence.

# 3. Network Design and Configuration

## 3.1 Objective

Design and configure two separate IPv4 networks and establish communication between them through a Windows Server routing infrastructure.

## 3.2 Network Topology

Two VMware host-only virtual networks are created.

| VMware Network | Network Type | Network Address |
|---|---|---|
| VMnet2 | Host-only | 192.168.10.0/24 |
| VMnet3 | Host-only | 192.168.20.0/24 |

The networks represent the Headquarters and Branch locations.

## 3.3 HQ Network Configuration

**Network:** 192.168.10.0/24

| Device | IPv4 Address | Subnet Mask | Gateway | DNS |
|---|---|---|---|---|
| DC-HQ | 192.168.10.10 | 255.255.255.0 | 192.168.10.254 | 192.168.10.10 |
| CLIENT-HQ | 192.168.10.20 | 255.255.255.0 | 192.168.10.254 | 192.168.10.10 |
| RTR-HQ-BRANCH | 192.168.10.254 | 255.255.255.0 | — | — |

## 3.4 Branch Network Configuration

**Network:** 192.168.20.0/24

| Device | IPv4 Address | Subnet Mask | Gateway | Initial DNS Configuration |
|---|---|---|---|---|
| DC-BRANCH | 192.168.20.10 | 255.255.255.0 | 192.168.20.254 | 192.168.10.10 |
| RTR-HQ-BRANCH | 192.168.20.254 | 255.255.255.0 | — | — |

The Branch Domain Controller's initial DNS configuration points to the HQ DNS server to support domain discovery and joining the existing domain.

## 3.5 Router Configuration

The Windows Server 2022 router has two network interfaces.

| Interface | IPv4 Address | Connected Network |
|---|---|---|
| Ethernet0 | 192.168.10.254/24 | VMnet2 |
| Ethernet1 | 192.168.20.254/24 | VMnet3 |

The router provides connectivity between the two subnets.

The configured network paths are:

```text
192.168.10.0/24
        |
        |
192.168.10.254
        |
   RTR-HQ-BRANCH
        |
192.168.20.254
        |
        |
192.168.20.0/24
```

The Windows Server routing infrastructure is configured to forward traffic between the two networks.

## 3.6 Network Validation

Check the IPv4 configuration:

```cmd
ipconfig /all
```

Test basic network connectivity.

From DC-HQ:

```cmd
ping 192.168.10.254
ping 192.168.20.254
ping 192.168.20.10
```

From DC-BRANCH:

```cmd
ping 192.168.20.254
ping 192.168.10.254
ping 192.168.10.10
```

From CLIENT-HQ:

```cmd
ping 192.168.10.10
ping 192.168.20.10
```

Successful connectivity confirms that the tested network paths are reachable.

- Static IPv4 configuration.

# 4. Active Directory Domain Services Deployment

## 4.1 Objective

Deploy a new Active Directory forest and domain, promote the HQ server as the first Domain Controller, and integrate the Branch server as an additional Domain Controller.

## 4.2 Domain Configuration

The Active Directory environment uses the following configuration:

| Parameter | Value |
|---|---|
| Forest Name | adlab.test |
| Domain Name | adlab.test |
| NetBIOS Name | ADLAB |
| Forest Functional Level | Windows Server 2016 |
| Domain Controller Operating System | Windows Server 2022 |

## 4.3 DC-HQ Preparation

On DC-HQ:

1. Configure the hostname as `DC-HQ`.
2. Configure the static IPv4 address.
3. Configure the preferred DNS server.
4. Verify network connectivity.
5. Open Server Manager.

Install the Active Directory Domain Services and DNS Server roles.

The role installation can be performed through:

```text
Server Manager
    > Manage
        > Add Roles and Features
            > Active Directory Domain Services
            > DNS Server
```

## 4.4 Promote DC-HQ

After installing AD DS:

1. Open Server Manager.
2. Select the notification flag.
3. Select Promote this server to a domain controller.
4. Select Add a new forest.
5. Enter:

```text
adlab.test
```

6. Configure the forest and domain functional levels as Windows Server 2016.
7. Enable DNS Server.
8. Keep Global Catalog enabled.
9. Configure the Directory Services Restore Mode (DSRM) password.
10. Complete the prerequisite checks.
11. Start the promotion process.
12. Allow the server to restart.

After restarting, DC-HQ becomes the first Domain Controller in the new forest.

## 4.5 Verify DC-HQ Services

Open PowerShell as Administrator:

```powershell
Get-Service NTDS,DNS,Netlogon,DFSR,KDC
```

Expected status:

```text
Running
```

Verify domain information:

```powershell
Get-ADDomain
```

Verify forest information:

```powershell
Get-ADForest
```

Check SYSVOL and NETLOGON shares:

```cmd
net share
```

The following shares should be available:

```text
SYSVOL
NETLOGON
```

## 4.6 DNS Configuration

The DNS role is installed as part of the Domain Controller deployment.

The Active Directory DNS zones include:

```text
adlab.test
_msdcs.adlab.test
```

These zones are configured as Active Directory-integrated DNS zones.

Verify DNS zones through PowerShell:

```powershell
Get-DnsServerZone
```

Check DNS records:

```powershell
Get-DnsServerResourceRecord -ZoneName "adlab.test"
```

Check Domain Controller discovery records:

```cmd
nslookup -type=SRV _ldap._tcp.dc._msdcs.adlab.test
```

## 4.7 DC-BRANCH Preparation

On DC-BRANCH:

1. Configure the hostname as `DC-BRANCH`.
2. Configure its static IPv4 address.
3. Configure its default gateway.
4. Configure its initial DNS server to point to DC-HQ.
5. Verify inter-site network connectivity.
6. Join the server to the existing domain `adlab.test`.

After joining the domain, install the AD DS and DNS Server roles.

## 4.8 Promote DC-BRANCH

Use Server Manager to promote DC-BRANCH.

1. Open Server Manager.
2. Select the notification flag.
3. Select Promote this server to a domain controller.
4. Select Add a domain controller to an existing domain.
5. Enter the domain:

```text
adlab.test
```

6. Supply an account authorized to perform the promotion.
7. Enable DNS Server.
8. Keep Global Catalog enabled.
9. Configure the DSRM password.
10. Complete the prerequisite checks.
11. Start the promotion process.
12. Restart the server when requested.

After the restart, DC-BRANCH becomes an additional Domain Controller in the existing domain.

## 4.9 Verify Both Domain Controllers

Run:

```powershell
Get-ADDomainController -Filter * |
Select-Object HostName,IPv4Address,Site,IsGlobalCatalog
```

Expected Domain Controllers:

| Hostname | IPv4 Address | Global Catalog |
|---|---|---|
| DC-HQ | 192.168.10.10 | True |
| DC-BRANCH | 192.168.20.10 | True |

Check replication summary:

```cmd
repadmin /replsummary
```

Check detailed replication status:

```cmd
repadmin /showrepl
```

Run basic Domain Controller diagnostics:

```cmd
dcdiag
```

The deployment was validated through service checks, DNS checks, directory replication checks, and SYSVOL/NETLOGON verification.

**Phase 04 Deliverables:**

- Active Directory forest and domain.
- Two promoted Domain Controllers.

- Global Catalog configuration.

# 5. Active Directory Sites and Services

## 5.1 Objective

Configure Active Directory Sites and Services to represent the two network locations and define the inter-site replication relationship.

```text
Server Manager
    > Tools
        > Active Directory Sites and Services
```

The initial environment contained the default site:

```text
Default-First-Site-Name
```

The initial configuration did not contain the intended HQ and Branch site separation.

## 5.3 Create HQ-Site

In Active Directory Sites and Services:

1. Right-click Sites.
2. Select New Site.
3. Enter:

```text
HQ-Site
```

4. Select the available site link.
5. Confirm the creation.

## 5.4 Create Branch-Site

Repeat the process and create:

```text
Branch-Site
```

Both sites are now available in the Active Directory site structure.

## 5.5 Create and Associate Subnets

Create the HQ subnet:

```text
192.168.10.0/24
```

Associate it with:

```text
HQ-Site
```

Create the Branch subnet:

```text
192.168.20.0/24
```

Associate it with:

```text
Branch-Site
```

This configuration enables Active Directory to associate IP addresses with the correct logical site.

## 5.6 Move Domain Controllers

Open:

```text
Sites
    > Default-First-Site-Name
        > Servers
```

Move the Domain Controller objects:

- Move DC-HQ to HQ-Site.
- Move DC-BRANCH to Branch-Site.

The default site is retained without these Domain Controller objects.

## 5.7 Configure the Site Link

Open:

```text
Sites
    > Inter-Site Transports
        > IP
```

Edit the default site link and configure:

| Setting | Value |
|---|---|
| Name | HQ-BRANCH-SiteLink |
| Site Membership | HQ-Site, Branch-Site |
| Cost | 100 |
| Replication Interval | 15 minutes |

Remove `Default-First-Site-Name` from the site link membership.

The resulting link connects the two intended sites.

## 5.8 Verify Site Configuration

Run on a Domain Controller:

```powershell
Get-ADDomainController -Filter * |
Select-Object HostName,Site,IPv4Address,IsGlobalCatalog
```

```text
DC-BRANCH   Branch-Site
```

```powershell
Select-Object Name,Site
```

Verify the site link:

```powershell
Get-ADReplicationSiteLink -Filter * |
Select-Object Name,Cost,ReplicationFrequencyInMinutes
```

Expected:

```text
Name: HQ-BRANCH-SiteLink
Cost: 100
ReplicationFrequencyInMinutes: 15
```

Verify the local site from each Domain Controller:

```cmd
nltest /dsgetsite
```

Expected:

- DC-HQ: HQ-Site.
- DC-BRANCH: Branch-Site.

## 5.9 Validate Replication

Run:

```cmd
repadmin /replsummary
```

Then:

```cmd
repadmin /showrepl
```

Force synchronization:

```cmd
repadmin /syncall /AdeP
```

The synchronization validation completed without errors, and subsequent replication summary checks reported zero failures.

Open Group Policy Management:

```text
Server Manager
    > Tools
        > Group Policy Management
```

Create:

```text
GPO-Domain-Account-Policy
```

Link the GPO to the domain root:

```text
adlab.test
```

Edit the GPO and navigate to:

```text
Computer Configuration
    > Policies
        > Windows Settings
            > Security Settings
                > Account Policies
```

### Password Policy

Configure:

| Policy | Value |
|---|---|
| Enforce Password History | 10 passwords |
| Maximum Password Age | 90 days |
| Minimum Password Age | 1 day |
| Minimum Password Length | 12 characters |
| Password Must Meet Complexity Requirements | Enabled |
| Store Passwords Using Reversible Encryption | Disabled |

### Account Lockout Policy

Configure:

| Policy | Value |
|---|---|
| Account Lockout Threshold | 5 invalid attempts |
| Account Lockout Duration | 15 minutes |
| Reset Account Lockout Counter After | 15 minutes |

The policy is linked at the domain root because domain password and lockout settings are domain-account policies.

These values represent the lab configuration and should be reviewed before use in a production environment.


Link it to:


| Policy | Value |
|---|---|

Navigate to:

## 7.7 Domain Controller Failure and Recovery

### Objective

Simulate the unavailability of the Branch Domain Controller and verify that the HQ-side infrastructure remains operational.

The test also verifies that DC-BRANCH can return to service and resume normal replication.

### Pre-Failure Health Check

Before shutting down DC-BRANCH, run:

```cmd
repadmin /replsummary
```

Check Domain Controller diagnostics:

```cmd
dcdiag /v
```

Record the current client logon server:

```cmd
echo %LOGONSERVER%
```

### Simulate Branch Domain Controller Failure

Using VMware Workstation:

1. Select the DC-BRANCH virtual machine.
2. Select Power.
3. Select Shut Down Guest.
4. Wait until the virtual machine is completely shut down.

A normal guest operating system shutdown is used rather than an abrupt power-off.

### Validate HQ Availability

While DC-BRANCH is offline, test connectivity from CLIENT-HQ:

```cmd
ping 192.168.10.10
```

Test HQ DNS:

```cmd
nslookup DC-HQ.adlab.test
```

Test Domain Controller discovery:

```cmd
nltest /dsgetdc:adlab.test
```

The expected result is successful discovery of an available Domain Controller, with DC-HQ remaining accessible.

### Authentication During Branch Outage

Sign out from CLIENT-HQ.

Sign in using a domain account that has previously logged on to the workstation.

Run:

```cmd
whoami
```

Then:

```cmd
echo %LOGONSERVER%
```

The logon server should identify DC-HQ for this test.

Using an account with previously cached credentials avoids confusing cached interactive logon with a first-time online authentication attempt.

### Recover DC-BRANCH

Start the DC-BRANCH virtual machine using VMware Workstation.

Allow Windows Server and Active Directory services to initialize.

Verify the required services:

```powershell
Get-Service NTDS,DNS,Netlogon,DFSR,KDC
```

Expected service state:

```text
Running
```

### Validate Replication After Recovery

On DC-HQ:

```cmd
repadmin /replsummary
```

Review detailed replication:

```cmd
repadmin /showrepl
```

Force synchronization:

```cmd
repadmin /syncall /AdeP
```

Expected result:

```text
SyncAll terminated with no errors.
```

Run the replication summary again:

```cmd
repadmin /replsummary
```

Confirm that replication has returned to a healthy state.

### Validate SYSVOL After Recovery

From CLIENT-HQ:

```cmd
dir \\DC-BRANCH\SYSVOL
```

Then:

```cmd
dir \\DC-BRANCH\NETLOGON
```

Successful access confirms that the Branch Domain Controller's shared resources are available again.

The failure/recovery validation confirmed that HQ remained available during the simulated Branch Domain Controller outage and that DC-BRANCH returned to service with replication restored.
