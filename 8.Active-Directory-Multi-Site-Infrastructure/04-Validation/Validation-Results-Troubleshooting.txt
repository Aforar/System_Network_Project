## 2. Executive Summary

This document presents the validation results for the Active Directory Multi-Site and Replication Infrastructure lab.

The validation phase was designed to verify that the deployed infrastructure operates correctly across both Active Directory sites. It covered user authentication, DNS resolution, Active Directory replication, SYSVOL and NETLOGON availability, Group Policy application, and basic domain controller failure recovery.

All planned validation categories were completed successfully.

The tests confirmed that:

- Domain users can authenticate against the Active Directory domain.
- DNS resolves the required domain records and service records.
- Active Directory replication operates between the two domain controllers.
- SYSVOL and NETLOGON shares are available.
- Group Policy settings are applied to the domain and workstation.
- The HQ domain controller remains available when the Branch domain controller is temporarily shut down.
- The Branch domain controller returns to service and replication is restored after restart.

The results demonstrate successful operation of the implemented lab configuration. They do not constitute a production readiness assessment or a full high-availability and disaster-recovery certification.

## 4. Validation Methodology

The validation process was divided into six testing categories.

| Test ID | Validation Category | Main Objective |
|---|---|---|
| VAL-01 | Authentication | Verify domain user authentication |
| VAL-02 | DNS | Verify domain and service-record resolution |

| VAL-05 | Group Policy | Verify policy application on the client |

Each test was performed using the relevant Windows administrative tools and command-line utilities.

## 5. Detailed Validation Results

### 5.1 VAL-01 — Authentication Validation

**Objective**

Verify that domain users can authenticate successfully and that the workstation communicates with an Active Directory domain controller.

**Test accounts**

| Account | Organizational Unit | Security Group |
|---|---|---|
| `it.admin` | `Users/IT` | `GG_IT_Support` |
| `hr.user` | `Users/HR` | `GG_HR` |
| `employee01` | `Users/General` | `GG_Employees` |

**Validation procedure**

1. Sign in to `CLIENT-HQ` using each test domain account.
2. Verify the authenticated identity.
3. Inspect the user's security group information.
4. Identify the domain controller used for the logon session.

**Commands used**

```cmd
whoami
whoami /all
echo %LOGONSERVER%
```

**Expected validation criteria**

- The user successfully signs in using domain credentials.
- `whoami` displays the correct domain identity.
- `whoami /all` displays the user's security information.
- `%LOGONSERVER%` identifies the domain controller handling the logon session.

**Result**

**PASS**

All three test accounts were successfully used for authentication validation. The identity and group information were inspected, and the logon server was identified.

### 5.2 VAL-02 — DNS Validation

**Objective**

Verify that DNS provides the name-resolution services required by Active Directory.

**Validation scope**

- Domain DNS resolution.
- Domain controller host records.
- LDAP service records.
- Kerberos service records.
- Active Directory DNS diagnostic checks.

**Commands used**

```powershell
Resolve-DnsName adlab.test
Resolve-DnsName DC-HQ.adlab.test
Resolve-DnsName DC-BRANCH.adlab.test

Resolve-DnsName _ldap._tcp.dc._msdcs.adlab.test -Type SRV
Resolve-DnsName _kerberos._tcp.dc._msdcs.adlab.test -Type SRV

dcdiag /test:dns /v
```

Additional DNS verification:

```cmd
nslookup adlab.test
nslookup DC-HQ.adlab.test
nslookup DC-BRANCH.adlab.test
```

**Expected validation criteria**

- The domain name resolves successfully.
- Both domain controllers can be resolved by hostname.
- LDAP and Kerberos SRV records are returned.
- DNS diagnostic tests complete successfully.

**Result**

**PASS**

DNS validation completed successfully. The domain and domain controller records were resolved, and the required Active Directory service records were verified.

**Evidence**

`Screenshots/Phase-07/02-DNS/`

### 5.3 VAL-03 — Active Directory Replication Validation

**Objective**

Verify that directory changes are replicated between `DC-HQ` and `DC-BRANCH`.

**Validation procedure**

1. Inspect the replication summary.
2. Review inbound replication status.
3. Trigger synchronization between domain controllers.
4. Create a temporary test user on the HQ domain controller.
5. Confirm that the object becomes available on the Branch domain controller.
6. Remove the temporary test account after validation.

**Commands used**

```cmd
repadmin /replsummary
repadmin /showrepl
repadmin /syncall /AdeP
```

**Replication test object**

```text
replication.test
```

**Expected validation criteria**

- Replication partners are visible.
- Replication operations complete successfully.
- No replication failures are reported in the completed validation.
- The temporary test object is replicated to the other domain controller.

**Result**

**PASS**

The replication checks completed successfully. The temporary test user `replication.test` was created on the HQ domain controller and confirmed on the Branch domain controller. The test object was subsequently removed.

**Evidence**

`Screenshots/Phase-07/03-Replication/`

### 5.6 VAL-06 — Domain Controller Failure Recovery

**Objective**

Evaluate the domain's ability to continue providing authentication services through the HQ domain controller while the Branch domain controller is temporarily unavailable.

This test also verifies that the Branch domain controller can return to service after restart.

**Test scenario**

The Branch domain controller was intentionally shut down to simulate a temporary domain controller outage.

**Test procedure**

1. Confirm that both domain controllers are operating normally.
2. Shut down `DC-BRANCH`.
3. Keep `DC-HQ` running.
4. Test domain authentication from `CLIENT-HQ`.
5. Inspect the logon server to identify the domain controller handling authentication.
6. Restart `DC-BRANCH`.
7. Verify that the Branch domain controller services return to the running state.
8. Confirm that replication and shared domain resources are available again.

**Commands used**

```cmd
echo %LOGONSERVER%
```

On the domain controller:

```powershell
Get-Service NTDS,DNS,Netlogon,DFSR,KDC
```

Replication verification:

```cmd
repadmin /replsummary
repadmin /showrepl
```

SYSVOL verification:

```cmd
net share
```

**Expected validation criteria**

- `DC-HQ` remains operational during the Branch outage.
- The client can authenticate through the available HQ domain controller.
- The logon server identifies `DC-HQ`.
- `DC-BRANCH` returns to service after restart.
- Required domain controller services are running.
- Replication and SYSVOL/NETLOGON availability are restored.

**Result**

**PASS**

The controlled failure-recovery test completed successfully.

During the temporary shutdown of `DC-BRANCH`, `DC-HQ` remained available. The client successfully completed the authentication test using a previously logged-on account, and the logon server information confirmed `DC-HQ`.

After restarting `DC-BRANCH`, its required services returned to the running state. Replication and SYSVOL/NETLOGON availability were verified again.

**Important limitation**

The authentication test used a previously logged-on account. Therefore, this test demonstrates continued authentication availability for that tested account under the lab conditions; it does not independently prove that every user can perform a first-time domain logon during a domain controller outage.

This controlled test also does not establish full production high availability, disaster recovery, or site-level fault tolerance.

## 7. Troubleshooting and Issue Resolution

The implementation and validation process included configuration checks and troubleshooting activities.

The following table records the relevant issues and corrective actions encountered during the project.

| Area | Issue or Observation | Corrective Action / Resolution |
|---|---|---|
| Network Configuration | Initial IP address conflict involving the HQ network configuration | Corrected the router/network addressing configuration and used `192.168.10.254` as the HQ gateway |
| Domain Controller DNS | DNS configuration required the HQ domain controller to be available during Branch domain joining and promotion | Used the HQ DNS server during the Branch domain controller deployment process |
| Replication | An earlier replication synchronization attempt reported a temporary topology or server reachability warning | Rechecked connectivity and replication configuration, then repeated synchronization and validation |
| DNS and Replication | An earlier replication check reported a temporary DNS lookup failure | Revalidated DNS resolution and repeated replication checks; subsequent validation completed successfully |
| SYSVOL / DFSR | An earlier DFS Replication diagnostic event was investigated during deployment | Continued DFSR and SYSVOL validation; the completed checks confirmed the expected SYSVOL state and successful validation |
| Client DNS | DNS response and server identification behavior was inspected during client-side troubleshooting | Verified the required domain records and service records using DNS validation commands |

The table records issues encountered during implementation and their subsequent resolution. It does not indicate that these issues remained active at the end of Phase 07.

## 10. Final Assessment

The validation phase confirmed that the implemented Active Directory Multi-Site infrastructure operates successfully under the tested lab conditions.

The two-site domain controller architecture supports directory replication between HQ and Branch. DNS provides the required domain and service-record resolution, while SYSVOL and NETLOGON remain available for domain operations.

The domain-joined workstation successfully authenticated using the configured test accounts and received the intended Group Policy configurations.

The controlled Branch domain controller outage test also demonstrated that the HQ domain controller remained available for the tested client authentication scenario. Following the restart of the Branch domain controller, the required services, replication, and shared resources were verified again.

## 11. Project Limitations

The results must be interpreted within the scope of the implemented lab.

The following capabilities were not established by the completed tests:

- Production-grade high availability.
- Full disaster recovery and recovery-time objectives.
- Automated failover between sites.
- Backup and restore validation for Active Directory.
- Security penetration testing.
- Continuous monitoring and alerting.
- Multi-client authentication testing during every possible failure scenario.
- Production WAN connectivity and VPN-based site-to-site communication.

These capabilities are outside the validated scope of this project.
